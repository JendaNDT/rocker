# W42 — manual update and compatible recovery

App version is generated from `Directory.Build.props` (candidate 0.2.0), native ABI is 15, SQLite schema 1, project format 1, backup format 1. Newer database/project/backup formats are refused rather than rewritten. No unattended download, restart or update task exists. Private handoff uses the exact GitHub repository/release and corresponding build commit; SHA256 and `build-info.json` verify integrity, not publisher authenticity. The package remains unsigned.

Setup keeps version directories and a previous-version shortcut, refuses a silent downgrade, and requires an explicit compatibility warning for a manual downgrade. It waits for the application to be closed through the app-held setup mutex; maintenance also refuses another running same-named process. Before switching the registered current path, it runs the new EXE's `--prepare-update` cold entry point. No audio host/window is created. This saves both a consistent raw SQLite copy and a full hash-checked `.rockerbackup` including recordings/projects plus version/schema metadata. Protected provider keys remain in their separate local store. Backup limit is the existing 2 GiB archive limit; insufficient space or incompatible data blocks the path switch and retains previous data/version. Setup can have copied the new version's files already; no current shortcut/state changes occur before a successful preflight.

A cold startup with an unsupported/corrupt profile now offers native recovery controls. A selected compatible archive is completely validated in a sibling profile before moving any original data. The full original profile stays in a retained sibling, including its original backups. DPAPI ciphertext is copied to the replacement for the same user. A bounded journal recovers interruption before/after publication without opening or overwriting a future database blindly. Successful recovery closes the application; the next Start shortcut launch uses the restored profile. Old backup directories remain in the retained profile rather than being silently deleted.

Infrastructure checks cover backup hash/raw SQLite, future-schema refusal, valid restoration with secret preservation, invalid archive preserving exact previous bytes, and injected interruption at prepared/retained/published boundaries. Windows setup checks execute the real maintenance EXE and validate its new archive/raw copy. A real prior-version installer compatibility run and extended downgrade UI test are recorded separately; synthetic version labels must not be described as authentic old binaries.
